# 제품 요구 사항 문서(PRD): 유튜브 인기급상승 영상 순위 수집 기능

## 1. 소개/개요

본 기능은 유튜브 인기급상승 페이지에서 쇼츠가 아닌 일반 영상들의 순위 정보를 자동으로 수집하여 저장하는 시스템입니다. 마케팅 담당자가 유튜브 트렌드를 분석하고 콘텐츠 전략을 수립할 수 있도록 일일 트렌드 데이터를 체계적으로 수집합니다.

**목표:** 유튜브 트렌드 분석을 위한 데이터 수집 자동화를 통해 마케팅 담당자의 의사결정을 지원합니다.

## 2. 목표

- **주요 목표:**
  - 유튜브 인기급상승 영상 데이터의 일일 자동 수집
  - 쇼츠를 제외한 일반 영상만 필터링하여 정확한 데이터 확보
  - 수집된 데이터를 통한 트렌드 분석 및 시각화 지원
  - 마케팅 전략 수립을 위한 인사이트 제공

- **측정 가능한 목표:**
  - 매일 오전 11시 정확한 데이터 수집 (성공률 95% 이상)
  - 상위 20개 영상 정보 완전 수집
  - 데이터 누락률 5% 이하 유지

## 3. 사용자 스토리

- **US-001:** 마케팅 담당자로서 매일 유튜브 인기급상승 영상 순위를 자동으로 수집하여 수동 작업 시간을 절약하고 싶습니다.
- **US-002:** 마케팅 담당자로서 쇼츠가 아닌 일반 영상만 필터링된 데이터를 얻어 정확한 트렌드 분석을 하고 싶습니다.
- **US-003:** 마케팅 담당자로서 수집된 데이터를 차트와 그래프로 시각화하여 직관적으로 트렌드를 파악하고 싶습니다.
- **US-004:** 마케팅 담당자로서 특정 채널이나 영상의 순위 변화를 추적하여 경쟁 분석을 하고 싶습니다.
- **US-005:** 마케팅 담당자로서 데이터 분석 및 통계를 통해 콘텐츠 전략을 수립하고 싶습니다.

## 4. 기능 요구 사항

### 4.1 데이터 수집 기능
1. 시스템은 매일 오전 11시에 유튜브 인기급상승 페이지에서 자동으로 데이터를 수집해야 합니다.
2. 시스템은 상위 20개 영상의 정보를 수집해야 합니다.
3. 시스템은 각 영상에 대해 다음 정보를 수집해야 합니다:
   - 수집 날짜
   - 영상 제목
   - 채널명(계정)
   - 순위
   - 영상 URL
   - 조회수
   - 게시일

### 4.2 필터링 기능
4. 시스템은 영상 URL 형식을 분석하여 쇼츠와 일반 영상을 구분해야 합니다.
5. 시스템은 쇼츠 영상을 제외하고 일반 영상만 저장해야 합니다.

### 4.3 데이터 저장 기능
6. 시스템은 수집된 데이터를 데이터베이스에 저장해야 합니다.
7. 시스템은 중복 데이터를 방지하기 위해 날짜별로 데이터를 관리해야 합니다.

### 4.4 시각화 기능
8. 시스템은 수집된 데이터를 차트와 그래프로 시각화하는 기능을 제공해야 합니다.
9. 시스템은 채널별 순위 변화 추이를 보여주는 기능을 제공해야 합니다.
10. 시스템은 일별, 주별, 월별 트렌드 분석을 지원해야 합니다.

### 4.5 분석 기능
11. 시스템은 수집된 데이터에 대한 기본 통계를 제공해야 합니다.
12. 시스템은 채널별 인기급상승 진입 횟수를 분석하는 기능을 제공해야 합니다.

### 4.6 오류 처리 기능
13. 시스템은 데이터 수집 실패 시 최대 3회까지 재시도해야 합니다.
14. 시스템은 최종 실패 시 오류 로그를 남겨야 합니다.
15. 시스템은 부분적 데이터 수집 실패 시에도 수집 가능한 데이터는 저장해야 합니다.

## 5. 비목표 (범위 외)

- 쇼츠 영상 데이터 수집
- 실시간 데이터 수집 (하루 1회만)
- 유튜브 API 사용 (웹 스크래핑 방식)
- 댓글 및 좋아요 수 데이터 수집
- 다른 플랫폼 (틱톡, 인스타그램 등) 데이터 수집
- 사용자 인증 및 권한 관리
- 데이터 내보내기 기능 (1차 버전)

## 6. 기술 고려 사항

- **데이터베이스:** PostgreSQL 또는 MySQL 사용 권장
- **스케줄링:** Cron job 또는 Spring Boot의 @Scheduled 어노테이션 활용
- **웹 스크래핑:** Selenium 또는 Jsoup 라이브러리 사용
- **차트 라이브러리:** Chart.js 또는 D3.js를 이용한 시각화
- **로깅:** SLF4J + Logback을 이용한 오류 로깅
- **데이터 무결성:** 트랜잭션 처리 및 백업 전략 필요

## 7. 디자인 고려 사항

- **대시보드:** 수집된 데이터를 한눈에 볼 수 있는 직관적인 대시보드
- **차트:** 순위 변화를 보여주는 라인 차트
- **테이블:** 날짜별 순위 데이터를 보여주는 정렬 가능한 테이블
- **필터:** 날짜 범위, 채널별 필터링 기능
- **반응형:** 모바일 및 태블릿에서도 사용 가능한 반응형 디자인

## 8. 성공 지표

- **데이터 수집 성공률:** 95% 이상
- **데이터 정확도:** 수동 확인 대비 98% 이상 일치
