# 제품 요구 사항 문서(PRD): 유튜브 인기급상승 영상 순위 수집 슬랙봇

## 1. 소개/개요

본 기능은 **슬랙봇**으로 구현되어 YouTube Data API를 통해 인기급상승 영상 중 쇼츠가 아닌 일반 영상들의 순위 정보를 자동으로 수집하여 저장하는 시스템입니다. 마케팅 담당자가 슬랙 채널에서 간편한 명령어를 통해 유튜브 트렌드를 분석하고 콘텐츠 전략을 수립할 수 있도록 일일 트렌드 데이터를 체계적으로 수집하고 제공합니다.

**목표:** 슬랙 환경에서 유튜브 트렌드 분석을 위한 데이터 수집 자동화 및 실시간 정보 제공을 통해 마케팅 담당자의 의사결정을 지원합니다.

## 2. 목표

- **주요 목표:**
  - 유튜브 인기급상승 영상 데이터의 일일 자동 수집
  - 쇼츠를 제외한 일반 영상만 필터링하여 정확한 데이터 확보
  - 슬랙 명령어를 통한 실시간 트렌드 조회 지원
  - 슬랙 채널 알림을 통한 자동 트렌드 리포트 제공
  - 마케팅 전략 수립을 위한 인사이트 제공

- **측정 가능한 목표:**
  - 매일 오전 11시 정확한 데이터 수집 (성공률 95% 이상)
  - 상위 20개 영상 정보 완전 수집
  - 데이터 누락률 5% 이하 유지
  - 슬랙봇 응답시간 3초 이내
  - 슬랙 명령어 성공률 98% 이상

## 3. 사용자 스토리

- **US-001:** 마케팅 담당자로서 슬랙에서 `/trending` 명령어를 통해 오늘의 유튜브 인기급상승 영상 순위를 빠르게 확인하고 싶습니다.
- **US-002:** 마케팅 담당자로서 슬랙에서 `/trending-channel [채널명]` 명령어를 통해 특정 채널의 인기급상승 이력을 조회하고 싶습니다.
- **US-003:** 마케팅 담당자로서 매일 오전 11시 30분에 슬랙 채널로 자동 전송되는 트렌드 리포트를 받아보고 싶습니다.
- **US-004:** 마케팅 담당자로서 슬랙에서 `/trending-stats` 명령어를 통해 주간/월간 트렌드 통계를 확인하고 싶습니다.
- **US-005:** 마케팅 담당자로서 슬랙에서 `/trending-alert [채널명]` 명령어를 통해 특정 채널이 인기급상승에 진입했을 때 알림을 받고 싶습니다.
- **US-006:** 마케팅 담당자로서 슬랙에서 `/trending-history [날짜]` 명령어를 통해 특정 날짜의 인기급상승 영상 순위를 확인하고 싶습니다.

## 4. 기능 요구 사항

### 4.1 데이터 수집 기능
1. 시스템은 매일 오전 11시에 YouTube Data API v3를 통해 인기급상승 영상 데이터를 자동으로 수집해야 합니다.
2. 시스템은 상위 20개 영상의 정보를 수집해야 합니다.
3. 시스템은 각 영상에 대해 다음 정보를 수집해야 합니다:
   - 수집 날짜
   - 영상 제목
   - 채널명(계정)
   - 순위
   - 영상 URL
   - 조회수
   - 게시일

### 4.2 필터링 기능
4. 시스템은 YouTube Data API 응답의 영상 길이(duration) 정보를 분석하여 쇼츠(60초 이하)와 일반 영상을 구분해야 합니다.
5. 시스템은 쇼츠 영상을 제외하고 일반 영상만 저장해야 합니다.

### 4.3 데이터 저장 기능
6. 시스템은 수집된 데이터를 데이터베이스에 저장해야 합니다.
7. 시스템은 중복 데이터를 방지하기 위해 날짜별로 데이터를 관리해야 합니다.

### 4.4 슬랙 명령어 기능
8. 시스템은 `/trending` 명령어를 통해 오늘의 인기급상승 영상 순위를 슬랙 메시지로 제공해야 합니다.
9. 시스템은 `/trending-channel [채널명]` 명령어를 통해 특정 채널의 인기급상승 이력을 제공해야 합니다.
10. 시스템은 `/trending-stats` 명령어를 통해 주간/월간 트렌드 통계를 제공해야 합니다.
11. 시스템은 `/trending-history [날짜]` 명령어를 통해 특정 날짜의 순위를 제공해야 합니다.

### 4.5 슬랙 알림 기능
12. 시스템은 매일 오전 11시 30분에 Chat.postMessage API를 통해 지정된 슬랙 채널로 자동 트렌드 리포트를 전송해야 합니다.
13. 시스템은 Chat.postMessage API를 활용하여 채널별, 사용자별 타겟팅이 가능한 유연한 메시지 전송을 지원해야 합니다.
14. 시스템은 `/trending-alert [채널명]` 명령어를 통해 특정 채널 알림을 설정할 수 있어야 합니다.
15. 시스템은 설정된 채널이 인기급상승에 진입했을 때 Chat.postMessage API를 통해 실시간 알림을 보내야 합니다.
16. 시스템은 Block Kit을 활용한 리치 메시지 형태로 구조화된 알림을 제공해야 합니다.
17. 시스템은 알림 메시지에 인터랙티브 버튼을 포함하여 사용자가 추가 정보를 요청하거나 알림 설정을 변경할 수 있어야 합니다.
18. 시스템은 알림 우선순위에 따라 메시지 색상을 다르게 표시해야 합니다 (일반: 파랑, 중요: 주황, 긴급: 빨강).
19. 시스템은 알림 메시지의 스레드 기능을 활용하여 채널 노이즈를 최소화해야 합니다.

### 4.6 메시지 포맷 기능
20. 시스템은 슬랙 메시지를 읽기 쉬운 형태로 포맷팅해야 합니다 (순위, 제목, 채널명, 조회수 포함).
21. 시스템은 슬랙 블록 킷을 활용하여 직관적인 메시지 레이아웃을 제공해야 합니다.
22. 시스템은 영상 링크를 클릭 가능한 형태로 제공해야 합니다.

### 4.7 오류 처리 기능
23. 시스템은 데이터 수집 실패 시 최대 3회까지 재시도해야 합니다.
24. 시스템은 최종 실패 시 오류 로그를 남기고 Chat.postMessage API를 통해 관리자 슬랙 채널로 알림을 보내야 합니다.
25. 시스템은 부분적 데이터 수집 실패 시에도 수집 가능한 데이터는 저장해야 합니다.
26. 시스템은 슬랙 명령어 실행 실패 시 사용자에게 친화적인 에러 메시지를 제공해야 합니다.
27. 시스템은 슬랙봇 다운타임 시 이메일 또는 SMS를 통한 대체 알림 방법을 제공해야 합니다.
28. 시스템은 동일 사용자의 연속 명령어 요청을 제한하여 스팸을 방지해야 합니다 (1분간 최대 5회).
29. 시스템은 비정상적인 대량 알림 발생 시 자동으로 알림을 일시 중단하고 관리자에게 통보해야 합니다.
30. 시스템은 YouTube API 할당량 초과 시 다음날까지 대기하고 관리자에게 알림을 보내야 합니다.
31. 시스템은 YouTube API 인증 실패 시 즉시 중단하고 관리자에게 긴급 알림을 보내야 합니다.

## 6. 기술 고려 사항

- **데이터베이스:** PostgreSQL 또는 MySQL 사용 권장
- **스케줄링:** Cron job 또는 Spring Boot의 @Scheduled 어노테이션 활용
- **YouTube API:** YouTube Data API v3 활용하여 안정적인 데이터 수집
- **슬랙 API:** Slack Web API 및 Slack Bolt Framework 활용
- **슬랙 명령어:** Slash Commands 구현
- **슬랙 메시지:** Block Kit을 활용한 리치 메시지 포맷
- **슬랙 알림:** Chat.postMessage API를 활용하여 채널별, 사용자별 타겟팅 지원 및 Block Kit 기반 리치 메시지 구현
- **로깅:** SLF4J + Logback을 이용한 오류 로깅
- **데이터 무결성:** 트랜잭션 처리 및 백업 전략 필요
- **보안:** 슬랙 앱 토큰, YouTube API 키 및 시크릿 안전한 관리
- **YouTube API 할당량 관리:** 일일 할당량 모니터링, 효율적인 API 호출 최적화, 할당량 초과 시 대체 방안
- **데이터 보관:** 3년간 데이터 보관 후 아카이빙 (법적 보관 의무 고려)
- **권한 관리:** 슬랙 앱 스코프 및 채널별 봇 권한 설정으로 사용 권한 제어
- **API 제한 대응:** YouTube Data API 및 슬랙 API Rate Limiting 준수, 요청 큐잉 및 재시도 로직 구현
- **데이터 백업:** 일일 자동 백업, 주간 증분 백업, 월간 전체 백업 전략
- **성능 최적화:** 6개월 이상 된 데이터 별도 아카이브 테이블로 이관

## 7. 디자인 고려 사항

- **슬랙 메시지 레이아웃:** 순위, 제목, 채널명, 조회수를 포함한 읽기 쉬운 메시지 구조
- **블록 킷 활용:** 헤더, 섹션, 디바이더를 활용한 구조화된 메시지
- **인터랙티브 요소:** Chat.postMessage API와 Block Kit 버튼을 활용한 추가 정보 조회 및 알림 설정
- **이모지 활용:** 순위 표시 및 시각적 구분을 위한 이모지 사용
- **메시지 길이 최적화:** 슬랙 메시지 제한에 맞춘 적절한 정보 표시
- **색상 코딩:** Chat.postMessage API의 attachments color 속성을 활용한 중요도별 메시지 색상 구분 (일반: 파랑, 중요: 주황, 긴급: 빨강)
- **링크 포맷:** 유튜브 영상 링크를 클릭 가능한 형태로 표시
