# 제품 요구 사항 문서(PRD): 유튜브 인기급상승 영상 순위 수집 슬랙봇

## 1. 소개/개요

본 기능은 **슬랙봇**으로 구현되어 유튜브 인기급상승 페이지에서 쇼츠가 아닌 일반 영상들의 순위 정보를 자동으로 수집하여 저장하는 시스템입니다. 마케팅 담당자가 슬랙 채널에서 간편한 명령어를 통해 유튜브 트렌드를 분석하고 콘텐츠 전략을 수립할 수 있도록 일일 트렌드 데이터를 체계적으로 수집하고 제공합니다.

**목표:** 슬랙 환경에서 유튜브 트렌드 분석을 위한 데이터 수집 자동화 및 실시간 정보 제공을 통해 마케팅 담당자의 의사결정을 지원합니다.

## 2. 목표

- **주요 목표:**
  - 유튜브 인기급상승 영상 데이터의 일일 자동 수집
  - 쇼츠를 제외한 일반 영상만 필터링하여 정확한 데이터 확보
  - 슬랙 명령어를 통한 실시간 트렌드 조회 지원
  - 슬랙 채널 알림을 통한 자동 트렌드 리포트 제공
  - 마케팅 전략 수립을 위한 인사이트 제공

- **측정 가능한 목표:**
  - 매일 오전 11시 정확한 데이터 수집 (성공률 95% 이상)
  - 상위 20개 영상 정보 완전 수집
  - 데이터 누락률 5% 이하 유지
  - 슬랙봇 응답시간 3초 이내
  - 슬랙 명령어 성공률 98% 이상

## 3. 사용자 스토리

- **US-001:** 마케팅 담당자로서 슬랙에서 `/trending` 명령어를 통해 오늘의 유튜브 인기급상승 영상 순위를 빠르게 확인하고 싶습니다.
- **US-002:** 마케팅 담당자로서 슬랙에서 `/trending-channel [채널명]` 명령어를 통해 특정 채널의 인기급상승 이력을 조회하고 싶습니다.
- **US-003:** 마케팅 담당자로서 매일 오전 11시 30분에 슬랙 채널로 자동 전송되는 트렌드 리포트를 받아보고 싶습니다.
- **US-004:** 마케팅 담당자로서 슬랙에서 `/trending-stats` 명령어를 통해 주간/월간 트렌드 통계를 확인하고 싶습니다.
- **US-005:** 마케팅 담당자로서 슬랙에서 `/trending-alert [채널명]` 명령어를 통해 특정 채널이 인기급상승에 진입했을 때 알림을 받고 싶습니다.
- **US-006:** 마케팅 담당자로서 슬랙에서 `/trending-history [날짜]` 명령어를 통해 특정 날짜의 인기급상승 영상 순위를 확인하고 싶습니다.

## 4. 기능 요구 사항

### 4.1 데이터 수집 기능
1. 시스템은 매일 오전 11시에 유튜브 인기급상승 페이지에서 자동으로 데이터를 수집해야 합니다.
2. 시스템은 상위 20개 영상의 정보를 수집해야 합니다.
3. 시스템은 각 영상에 대해 다음 정보를 수집해야 합니다:
   - 수집 날짜
   - 영상 제목
   - 채널명(계정)
   - 순위
   - 영상 URL
   - 조회수
   - 게시일

### 4.2 필터링 기능
4. 시스템은 영상 URL 형식을 분석하여 쇼츠와 일반 영상을 구분해야 합니다.
5. 시스템은 쇼츠 영상을 제외하고 일반 영상만 저장해야 합니다.

### 4.3 데이터 저장 기능
6. 시스템은 수집된 데이터를 데이터베이스에 저장해야 합니다.
7. 시스템은 중복 데이터를 방지하기 위해 날짜별로 데이터를 관리해야 합니다.

### 4.4 슬랙 명령어 기능
8. 시스템은 `/trending` 명령어를 통해 오늘의 인기급상승 영상 순위를 슬랙 메시지로 제공해야 합니다.
9. 시스템은 `/trending-channel [채널명]` 명령어를 통해 특정 채널의 인기급상승 이력을 제공해야 합니다.
10. 시스템은 `/trending-stats` 명령어를 통해 주간/월간 트렌드 통계를 제공해야 합니다.
11. 시스템은 `/trending-history [날짜]` 명령어를 통해 특정 날짜의 순위를 제공해야 합니다.

### 4.5 슬랙 알림 기능
12. 시스템은 매일 오전 11시 30분에 지정된 슬랙 채널로 자동 트렌드 리포트를 전송해야 합니다.
13. 시스템은 `/trending-alert [채널명]` 명령어를 통해 특정 채널 알림을 설정할 수 있어야 합니다.
14. 시스템은 설정된 채널이 인기급상승에 진입했을 때 실시간 알림을 보내야 합니다.

### 4.6 메시지 포맷 기능
15. 시스템은 슬랙 메시지를 읽기 쉬운 형태로 포맷팅해야 합니다 (순위, 제목, 채널명, 조회수 포함).
16. 시스템은 슬랙 블록 킷을 활용하여 직관적인 메시지 레이아웃을 제공해야 합니다.
17. 시스템은 영상 링크를 클릭 가능한 형태로 제공해야 합니다.

### 4.7 오류 처리 기능
18. 시스템은 데이터 수집 실패 시 최대 3회까지 재시도해야 합니다.
19. 시스템은 최종 실패 시 오류 로그를 남기고 관리자 슬랙 채널로 알림을 보내야 합니다.
20. 시스템은 부분적 데이터 수집 실패 시에도 수집 가능한 데이터는 저장해야 합니다.
21. 시스템은 슬랙 명령어 실행 실패 시 사용자에게 친화적인 에러 메시지를 제공해야 합니다.

## 5. 비목표 (범위 외)

- 쇼츠 영상 데이터 수집
- 실시간 데이터 수집 (하루 1회만)

- 복잡한 차트 및 그래프 생성
- 슬랙 외부 플랫폼 연동

## 6. 기술 고려 사항

- **데이터베이스:** PostgreSQL 또는 MySQL 사용 권장
- **스케줄링:** Cron job 또는 Spring Boot의 @Scheduled 어노테이션 활용
- **웹 스크래핑:** Selenium 또는 Jsoup 라이브러리 사용
- **슬랙 API:** Slack Web API 및 Slack Bolt Framework 활용
- **슬랙 명령어:** Slash Commands 구현
- **슬랙 메시지:** Block Kit을 활용한 리치 메시지 포맷
- **슬랙 알림:** Incoming Webhooks 또는 Chat API 사용
- **로깅:** SLF4J + Logback을 이용한 오류 로깅
- **데이터 무결성:** 트랜잭션 처리 및 백업 전략 필요
- **보안:** 슬랙 앱 토큰 및 시크릿 관리

## 7. 디자인 고려 사항

- **슬랙 메시지 레이아웃:** 순위, 제목, 채널명, 조회수를 포함한 읽기 쉬운 메시지 구조
- **블록 킷 활용:** 헤더, 섹션, 디바이더를 활용한 구조화된 메시지
- **인터랙티브 요소:** 버튼을 통한 추가 정보 조회 및 알림 설정
- **이모지 활용:** 순위 표시 및 시각적 구분을 위한 이모지 사용
- **메시지 길이 최적화:** 슬랙 메시지 제한에 맞춘 적절한 정보 표시
- **색상 코딩:** 중요도에 따른 메시지 색상 구분 (성공: 초록, 경고: 노랑, 에러: 빨강)
- **링크 포맷:** 유튜브 영상 링크를 클릭 가능한 형태로 표시
